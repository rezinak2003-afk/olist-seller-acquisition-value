# Olist Seller Acquisition Funnel → 90-Day Marketplace Value

**Portfolio case study | SQL · Python · Excel · Power BI · Statistics**

## Executive question

Which recorded marketing origins convert qualified leads into closed seller deals, and what marketplace outcomes are observable during those sellers' first 90 days after winning?

The analysis separates lead conversion, seller-ID linkage and post-win outcomes among mature linked sellers. This avoids treating missing marketplace linkage as zero GMV or ranking acquisition origins using incomplete outcome data.

## Audit corrections

|Correction|What was wrong|What changed|
|-|-|-|
|**C1 — observation cutoff**|Maturity relied on the absolute latest order timestamp, so a sparse tail could falsely mature deals|Python and SQL now use the day after the last calendar day with at least 50 purchases; `data_end` is explicit, sensitivity is 10/50/100 orders per day, validation checks leakage, and a sparse-tail unit test is included|
|**C2 — SQL contract and parity**|Python/SQL date types and duplicate DDL could drift|`won_date` is `TIMESTAMP`, `00_schema.sql` is the single DDL source, keys/indexes are defined, and the runner compares every seller-mart/channel-summary column plus reconciliation totals and close-day sums/counts|
|**C3 — statistical inference**|Two isolated tests and BH reporting understated the multiple-comparison problem; the five-group expected counts did not support an asymptotic chi-square assumption|Pairwise Fisher tests now cover all eligible origin pairs (n≥20) with Holm correction; Newcombe difference CIs and fixed-margin Monte Carlo omnibus tests are generated for both activation definitions|
|**C4 — linkage and claim discipline**|Seller linkage was incomplete and could bias linked-only channel comparisons; unlinked outcomes must not be treated as zero|Linkage is reported by origin, lead type, segment and win month; a propensity model and capped stabilized IPW sensitivity are added; the report uses the observed numerator / all-mature lower bound and makes no causal claim|
|**C5 — outcome-dependent linkage**|Seller linkage used any observed item sale, including after the 90-day outcome window|Worst-case all-mature bounds, paid/organic tipping scenarios, first-sale timing and Kaplan–Meier time-to-first-sale outputs now quantify the selection risk|
|**C6 — model instability**|The original full logistic model was over-parameterised for 58 non-events|A reduced L2-penalized origin + lead-type model (alpha=0.05) pools rare levels, reports EPV=5.8, omits penalized-model p-values and labels intervals exploratory|
|**C7 — quality sensitivity**|Payment reconciliation was previously unavailable and anomaly impact/maturity sensitivity were incomplete|Payment tolerance checks now run on 98,665 comparable orders; delivery-date anomaly impacts and activation/GMV at 10/50/100 thresholds are reported|

## Important limitations

* Seller-ID linkage is incomplete; unmatched seller outcomes are unknown, not zero. The linked subset may differ systematically from the unlinked deals.
* The 50-purchases/day cutoff is a conservative data-maturity rule, not a natural dataset boundary; 10/50/100-day-volume sensitivity is shown.
* Channel origin is observational. No spend, randomized assignment or counterfactual is supplied, so CAC, ROI, payback and causal uplift cannot be calculated.
* GMV is order-item `price` in BRL; it excludes freight and does not represent seller profit or platform revenue.
* The purchase-window definition uses purchase date and the delivered status in the extract; strict activation additionally requires delivery within the 90-day window.
