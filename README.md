## Executive question

Which recorded marketing origins convert qualified leads into closed seller deals, and what marketplace outcomes are observable during those sellers' first 90 days after winning?

The analysis separates lead conversion, seller-ID linkage and post-win outcomes among mature linked sellers. This avoids treating missing marketplace linkage as zero GMV or ranking acquisition origins using incomplete outcome data.

## Audit corrections

|Correction|What was wrong|What changed|
|-|-|-|
|**C1 â€” observation cutoff**|Maturity relied on the absolute latest order timestamp, so a sparse tail could falsely mature deals|Python and SQL now use the day after the last calendar day with at least 50 purchases; `data\_end` is explicit, sensitivity is 10/50/100 orders per day, validation checks leakage, and a sparse-tail unit test is included|
|**C2 â€” SQL contract and parity**|Python/SQL date types and duplicate DDL could drift|`won\_date` is `TIMESTAMP`, `00\_schema.sql` is the single DDL source, keys/indexes are defined, and the runner compares every seller-mart/channel-summary column plus reconciliation totals and close-day sums/counts|
|**C3 â€” statistical inference**|Two isolated tests and BH reporting understated the multiple-comparison problem; the five-group expected counts did not support an asymptotic chi-square assumption|Pairwise Fisher tests now cover all eligible origin pairs (nâ‰¥20) with Holm correction; Newcombe difference CIs and fixed-margin Monte Carlo omnibus tests are generated for both activation definitions|
|**C4 â€” linkage and claim discipline**|Seller linkage was incomplete and could bias linked-only channel comparisons; unlinked outcomes must not be treated as zero|Linkage is reported by origin, lead type, segment and win month; a propensity model and capped stabilized IPW sensitivity are added; the report uses the observed numerator / all-mature lower bound and makes no causal claim|

## Reproduce the Python analysis

```bash
python -m venv .venv
# Windows: .venv\\\\Scripts\\\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m src.pipeline
python -m pytest -q -m "not integration"
python -m src.make\_charts
python scripts/build\_dashboard.py
python scripts/update\_readme\_results.py
```

The pipeline writes the seller mart, acquisition funnel, validation checks, pairwise tests, linkage and IPW diagnostics, adjusted activation model, window sensitivity, cumulative activation curve, GMV concentration and payment reconciliation outputs under `data/processed/`. `docs/CLEANING\_LOG.md` records the corrections and exception counts.

## Execute PostgreSQL end to end

With Docker Desktop or PostgreSQL 16 available:

```bash
docker compose -f compose.yaml up -d postgres
cp .env.example .env
pip install -r requirements.txt
python -m src.pipeline
python scripts/run\_postgres.py
```

The runner recreates `raw` and `mart` from the single DDL file, loads the four source CSVs, executes SQL validation and marts, and compares every seller mart and channel summary column with Python. It also checks `close\_days` aggregates and each source control from `05\_reconciliation.sql`. It writes `data/processed/sql\_python\_reconciliation.csv` and exits non-zero if any check is not `PASS`. Do not claim parity until the file exists and every row passes.

## Important limitations

* Seller-ID linkage is incomplete; unmatched seller outcomes are unknown, not zero. The linked subset may differ systematically from the unlinked deals.
* The 50-purchases/day cutoff is a conservative data-maturity rule, not a natural dataset boundary; 10/50/100-day-volume sensitivity is shown.
* Channel origin is observational. No spend, randomized assignment or counterfactual is supplied, so CAC, ROI, payback and causal uplift cannot be calculated.
* GMV is order-item `price` in BRL; it excludes freight and does not represent seller profit or platform revenue.
* The purchase-window definition uses purchase date and the delivered status in the extract; strict activation additionally requires delivery within the 90-day window.
